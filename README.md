# Minecraft AI 建造助手（minecraft-ai）

一个 Fabric 模组：在游戏里用一句话描述你的想法，**AI 亲手把它一格一格画出来**（`kind:"freeform"` 自由形体契约），
3D 预览确认后一键建造，随时可撤销；不满意可以继续用一句话提意见迭代调整。
生成过程在后台运行，关掉面板也不中断。

> 适用版本：Minecraft **26.1.2** + Fabric Loader **≥0.19.0** + Fabric API **0.155.2+26.1.2** + Java **≥24**

**核心立场：形状完全由你的提示词决定 —— 程序里没有任何建筑模板。** 船、飞机、雕像、桥、茶室、四合院、
城堡、住宅楼、写字楼、商场……全部由 AI 用 ops 绘制指令现画；程序只负责把指令翻译成方块，
外加"栏杆自动连片 / 灯笼自动吊挂 / 孤立方块体检"这类兜底，不做任何形状假设。

## v1.1.1 做了什么（相对 v1.1.0）

修掉「AI 无限卡死」并把主界面改成**对话式**（常见 AI 聊天布局 + Minecraft 像素风）。

| 改动 | 说明 |
| --- | --- |
| **流式 `stream:true` + 空闲超时** | 不再用非流式死等完整响应体。响应体阶段若超过空闲秒数（默认 45s，可配）无新数据就断开；另设生成总时长与思考预算 |
| **两阶段生成** | ① 先出短 JSON「设计要点」（外形/尺寸/mirror/材质/部件）→ ② 按要点画紧凑 freeform `ops`（优先 box、ops≤25、能 mirror 就 mirror）。思考更快结束、输出更短，形状仍完全由 AI 现画 |
| **对话式界面** | 底部提示词 +「发送」；上方起点/终点坐标；消息气泡流；**思考过程可展开/折起**；生成后消息内 3D 预览 +「确认建造」；同一会话继续说 = 修改；「新建会话」= 新建筑 |
| **多会话** | 顶部会话标签可切换；生成中可取消；设置入口保留（含空闲超时秒数） |
| **取消/超时不再误报** | 用户取消才显示「已取消」；空闲/总超时/思考超预算会显示真实原因；关思考后模型仍 reasoning 时不再误判成「思考超预算」 |
| **关思考更彻底** | 多 API 方言禁用思考（`thinking:disabled` / `enable_thinking=false` / `chat_template_kwargs`）；后端拒字段时自动最小体重试 |

## v1.1.0 做了什么（相对 v1.0.2）

v1.0.2 让 AI 画 **8~24 格的字符画蓝图**（`# W D P S R B C F L T X`）+ 三个全局颜色字段。
信息密度太低：层高、户型、房间语义、家具、楼梯、电梯、屋面构件、方块朝向都没有地方表达，
模型只能退化成"方盒子 + 每层复制"，玩家写得再细也落不进去。

v1.1.0 把底层换成 **设计规格（DSL）→ 构件展开 → 方案体检** 三段式
（**最新补丁已把"参数化构件库 / 建筑模板"整条删掉**，最终只剩"AI 自己画"一条路 —— 见下表）：

| 改动 | 说明 |
| --- | --- |
| **新契约** | AI 只输出设计规格 JSON，不再输出字符画 |
| **参数化构件库**（已随模板删除） | 房间、门窗、双跑楼梯、脚手架电梯井、阳台、女儿墙、屋面设备、家具库曾由本地代码确定性生成；模板删除后全部改由 AI 的 `ops` 画 |
| **方案体检 + 自动修补**（已随模板删除） | 悬空方块、楼板空洞、堵门、房间可达性曾逐项检查并自动修；现在唯一路径 freeform **故意不做体检**（悬空是船帆/桅杆的常态），改为只报告不修补的轻量审计 |
| **blockstate 支持** | `BuildingPlan.Entry` 带方块状态属性：楼梯朝向、半砖、脚手架 distance、门/床朝向等都能精确落地 |
| **notes 落实**（已随模板删除） | 以前会把 `notes` 里的关键词（阳台/电梯/坡屋顶/太阳能/层数/外墙颜色…）解析成生效字段；现在 `notes` **只是备注**，要什么请直接用 `ops` 画 |
| **门策略**（已随模板删除） | 以前建筑内只生成木门、不生成铁门与按钮/压力板，门楣自动补墙、门口自动清障；现在门窗全由 AI 的 `ops` 决定 |
| **预览优化** | 只画暴露面 + 块被包住就不画；方块太多时按 2×2×2/3×3×3 **合并降分辨率**（不是随机抽稀）；跳过屏幕亚像素方块；打字时自动降档，保证输入流畅 |
| **错误诊断** | HTTP 状态码分类成人话（401 鉴权 / 402 额度 / 429 限流 / 5xx 服务端错误…），5xx/429/超时 **自动退避重试**；服务端拒绝 `thinking` 参数时自动去掉重试 |
| **配置修复** | 修复"打开设置再保存就把 API Key 截断成 32 字符"的 bug（EditBox 必须先 `setMaxLength` 再 `setValue`）；启动日志打印 Key 长度便于排查 |
| **自由形体通道**（后续补丁） | 修掉"让 AI 造一艘船却得到二层小楼、而且怎么调整都一样"：新增 `kind:"freeform"` 契约 + `FreeformBuilder`（分层字符画 / box / clear / cyl / sphere / 镜像），程序逐格照做；并加 `mismatchHint` 自动重做兜底 |
| **默认由 AI 自己画**（后续补丁） | 提示词第一步从"判断建筑还是自由形体"改成**"默认就是你自己画（freeform）"**；`kind:"building"` 降级为"玩家点名时才用" |
| **通用户型模板已删除**（后续补丁） | `SpecBuilder` 里删掉 `genericModel()`（那个"方盒子 + 房间网格"的通用户型），建筑模板只剩 `chinese_highrise`；archetype 不符或框选放不下核心筒（最小 25×17）时**明确报错、绝不静默降级** |
| **★ 建筑模板全部删除**（最新补丁） | **程序不再提供任何建筑模板**：`kind:"building"` 与 `archetype` 已无任何实现。AI 仍写它时**直接当成 `freeform`**（不报错、不特判）；它若因此没给出 `ops`，就展开成 0 个方块 + 明确警告，由 `BuildTaskManager` 带着原因要求模型重画。同时删掉旧版字符画管线（`PlanGenerator` / `PlanParser` / `PlanSpec` / `NotesParser` / `PartLib` / `Interiors` / `Layout`，共约 1530 行）。jar 从 **165583 → 106798 字节**（−35.5%） |
| **freeform 补 blockstate**（最新补丁） | `ops` 支持 `props`：楼梯朝向/半砖/栅栏门/挂灯/横梁原木都能画了；镜像时自动翻转 `facing`/`hinge`/`shape`/`rotation`/栏杆连接方向 |
| **freeform 轻量体检**（最新补丁） | 只报告不修补：`autoHanging`（灯笼上方实心→吊灯）、`connectPass`（栏杆/玻璃板按真实邻居连片）、`audit`（统计孤立方块）。**绝不删改** —— 船帆/桅杆/机翼的合法悬空不能被误伤 |

## 功能特性

- **一句话生成任意东西**（`kind:"freeform"`，也是唯一契约）：船、飞机、飞船、雕像、桥、家具、风车、茶室、
  四合院、城堡、住宅楼、写字楼、商场…… AI 用分层字符画 + 长方体/圆柱/球体 + 镜像 + blockstate 属性
  直接描述，程序逐格照做（不会再把船做成二层小楼，也不会再把别墅套成住宅楼）
- **结果校验 / 自动重做**：程序会机械检查三类不合格输出 —— ①还在用**已删除**的旧格式
  （`floors_map` 字符画蓝图、`kind:"building"` + `archetype`）、②规格里一个 `ops` 都没有、
  ③调整后什么都没改；发现不合格就把错误明确指回给模型让它重做一次
- **可交互 3D 预览**：滚轮缩放、右键拖拽无级旋转、左键拖拽平移、双击复位；大建筑自动适配视口
- **后台生成 + 悬浮球**：生成期间可关面板继续玩，右上角像素风悬浮球显示秒数/成功/失败，按 K 查看结果
- **方案迭代调整**：载入上次方案 + 提意见 → AI 只改受影响字段并返回完整新规格；建造后调整会**自动替换**旧建筑
- **一键建造 / 撤销**：批量放置整栋建筑，支持一键撤销
- **空间约束**：可指定终点坐标限制范围；超出时提示（按完整方案放置，不裁剪）
- **游戏内配置**：OpenAI 兼容接口 / 本地 Ollama 一键切换，填 Base URL、模型、API Key、思考模式，保存即时生效

## 设计规格（AI 输出的 JSON）

**只有一种契约：`kind:"freeform"`。** 程序里没有任何建筑模板 —— 形状完全由 AI 的 `ops` 决定。
（历史版本里的 `kind:"building"` + `archetype` 已随全部模板一起删除；AI 仍写它时会被**直接当成 `freeform`**，
它若因此没给出 `ops`，就会展开成 0 个方块并由程序带着原因要求模型重画。）

### 自由形体（`kind:"freeform"` —— 唯一契约：船/飞机/雕像/桥/别墅/茶室/住宅楼/写字楼…都走这里）

```json
{
  "spec_version": 3,
  "kind": "freeform",
  "name": "帆船",
  "size": [15, 9, 9],
  "palette": { "h": "dark_oak_planks", "m": "oak_log", "s": "white_wool" },
  "mirror": "x",
  "ops": [
    { "op": "layer", "y": 0, "rows": [".....hhh", "....hhhh", "...hhhhh", "..hhhhhh", ".hhhhhhh"] },
    { "op": "layer", "y": 2, "rows": [".....ddd", "....dddd", "...ddddd", "..dddddd", ".ddddddd"] },
    { "op": "cyl", "x": 7, "z": 4, "r": 0, "y0": 3, "y1": 8, "block": "m" },
    { "op": "layer", "y": 6, "rows": ["..........", ".....sss..", "....ssss..", "...sssss..", "..ssssss.."] }
  ]
}
```

- `size`：`[宽X, 高Y, 进深Z]`（也可只给 `[宽, 进深]`）；缺省时按 ops 实际范围自动算
- `palette`：单字符 → 方块 id（缺省可用内置表：`#`石砖 `O`橡木板 `o`橡木原木 `W`白羊毛 `G`玻璃 `I`铁块 `L`灯笼 `X`海晶灯 …）
- `mirror`：`none` / `x` / `z` / `xz` —— **只写一半，程序镜像另一半**（朝向/铰链/楼梯形状/栏杆连接方向都会自动翻好）
- `ops`：`layer`（分层字符画）/ `box`（长方体，`hollow` 只做六面壳）/ `clear`（掏空）/ `cyl`（竖直圆柱）/ `sphere`（球/椭球），按顺序执行，后面的覆盖前面的
- `props`（可选，blockstate 属性）：`facing` `half` `type` `axis` `hinge` `open` `shape` `hanging` `rotation`…
  例如 `{"op":"box","from":[1,1,5],"to":[1,1,5],"block":"dark_oak_stairs","props":{"facing":"north","half":"bottom"}}`。
  `{"block":"air"}` 会被当成"删除"，不会往方案里塞空气条目
- **不做建筑逻辑**：不铺楼板、不开窗、不摆家具、不加屋顶（这些都是 AI 自己用 ops 画）
- **不做 `PlanValidator` 体检**（否则船帆/桅杆会被当成"悬空方块"删掉）；改为只报告不修补的三道后处理：
  灯笼上方实心自动吊挂、栏杆/玻璃板按真实邻居自动连片、统计孤立方块（六邻居全空）写进日志
- 安全阀：坐标越界与非法方块 id 一律丢弃；方块数上限 100000（超了直接报错，不会卡死游戏）；单边上限 128

## 安装

1. 安装 [Fabric Loader](https://fabricmc.net/use/) 与 Minecraft 26.1.2
2. 从 [Releases](https://github.com/xhmzlzg/minecraft-ai-builder/releases) 下载 jar，与 `fabric-api` 一起放进 `.minecraft/versions/<版本>/mods/`
3. 启动游戏

## 使用

1. 游戏内按 **K** 打开"AI 建造助手"
2. 写描述（建议写清层数），设置起点坐标（默认玩家面前 10 格），终点可留空
3. 点「生成方案」，等 AI 回复（生成期间可按 ESC 继续玩，看右上角悬浮球）
4. 在预览区滚轮缩放 / 右键旋转 / 左键平移检查
5. 满意点「确认建造」；反悔点「撤销上次」

### 迭代调整

- 点「调整上次方案」→ 自动载入上次方案与坐标 → 写调整意见 → 点「确认调整」
- 日志会打印 `调整前后规格差异:` 与 `notes 落实:`，能直接看出这次到底改了什么
- 对调整后的方案点「确认建造」会**自动撤销旧建筑并重建**

### 配置

- 面板 →「设置」：切换 **OpenAI 兼容** / **本地 Ollama**，填 Base URL、模型名、API Key（Ollama 填地址与模型）
- 配置文件：`config/minecraft-ai.json`（**API Key 只存在本地，不会进仓库/Release**）
- 提示：不少厂商的 `/models` 接口不支持或有额外鉴权，面板预检失败只是**提示**，直接点生成即可；真正的错误会按 HTTP 状态码明确报出来

## 源码结构（`src/main/java` + `src/client/java`，包 `com.mcai`）

```
common/
  BuildingPlan.java        方案数据：Entry 带 blockstate 属性；可覆盖/删除
  PlanValidator.java       方案体检 + 自动修补（悬空/楼板空洞/堵门/可达/安装面判定）
  BuildingExecutor.java    服务端放置（按属性名还原 blockstate）、撤销栈
  spec/
    BuildingSpec.java      规格外壳（spec_version / kind / name / freeform）
    FreeformSpec.java      自由形体 DTO（唯一契约）+ 内置字符表 + op 的 props
    FreeformBuilder.java   展开器：逐格照做 + 镜像翻转朝向 + 自动吊挂/连片/孤立审计（只报告不修补）
    SpecParser.java        宽容解析（别名/代码块/尾随逗号/嵌 blockstate/minecraft: 前缀）
    SpecBuilder.java       规格 → 方案（只做 freeform 分发）
client/
  ai/AiClient.java         AI 请求（OpenAI 兼容/Ollama）+ 错误分类 + 自动重试 + 纠正提示
  ai/BuildTaskManager.java 全局任务 + 悬浮球 + 规格差异日志 + 结果校验/自动重做
  gui/AiBuildScreen.java   主面板（描述/坐标/5 按钮/预览/状态）
  gui/AiConfigScreen.java  配置界面
  render/PlanPreviewWidget.java  3D 预览（暴露面剔除 + 粗格 LOD）
selftest/SpecSelfTest.java  离线自检（不开游戏验证几何）
tools/selftest.bat          一键跑自检
docs/SPEC_v1.1.0.md         契约与实现说明
```

## 构建与自检

```bat
gradlew.bat build                 :: 产物 build\libs\minecraft-ai-1.1.0.jar
tools\selftest.bat                :: 离线自检：113 项断言，不开游戏验证几何
```

自检覆盖：镜像对称、不是方盒子楼、悬空帆/桅杆不被删、越界与非法 id 被丢弃、巨物被拦下、
`props` 透传与镜像朝向翻转、栏杆自动连片、灯笼自动吊挂、孤立方块审计只报告不修补、
`{"block":"air"}` 当成删除，以及**提示词里两段 few-shot 示例自身必须合格**（帆船 + 两层木屋）。

另有一节专门守"**模板真的没了**"：`kind:"building"` 必须被当成 freeform、旧格式必须解析为 null、
以及 7 个旧类必须从 classpath 上消失（`Class.forName` 抛异常）—— 专治"删了引用没删文件"。
最后一节做全组合压力测试（44 个组合）：不崩溃、**空方案必带警告**、没有"每个组合都触发"的假警告。

还有一节专门盯**模型常见畸形写法**（这些以前都会让方块被静默丢弃，重则整个方案变成 0 个方块）：
`"block":"oak_stairs[facing=east]"` 这种把 blockstate 嵌在方块名里的写法、带 `minecraft:` 前缀、
palette 值里嵌状态、`mirror:"both"`、多个 layer 都不写 `y`、layer 字符不在 palette 里时用 `op.block` 兜底，
以及"真的一格都画不出来"时方案能被识别为空并触发自动重做。

请求层不再限制输出长度：**不发送 `max_tokens`**，由服务端按自己的上限决定（等于无限制）。
以前写死 8192 两头都是坑 —— 服务端默认只有 1024/2048 时会**截断**（截断后的 JSON 必然解析失败，
症状和"AI 不听话"几乎一样，很容易误判），而写死一个大值又可能超过某些模型的上限被直接 4xx 拒掉。
真被截断时日志里会写 `finish_reason=length`，并提示你让作品画简单些或关掉思考模式。

## 已知限制

- 仅单人游戏（内置服务器）
- 大体量建筑（例如 30 层以上）一次放置耗时较长，建议描述里写明层数或用框选高度限制
- **模型可能仍沿用旧格式**：玩家说"别墅/四合院/城堡/公寓楼"时，模型第一次仍可能给 `kind:"building"`；
  它会被当成 freeform，若没带 `ops` 就会被打回重做一次 —— 靠提示词强度压低首次出错率
- **提示词较长**（含两段 few-shot 示例：帆船 + 两层木屋），每次请求都要发；换来的是首次命中率
  （模板删除后已把"契约 B：建筑"与建筑硬性规则整段删掉，比之前更短）
- 自由形体**按完整方案放置、不按框选裁剪**：比框选高的作品会长到框外，日志会给提示
- 自由形体**不做自动体检**（只有"孤立方块"这类只读审计）：AI 自己画的房子里可能有悬空件或走不进去的房间
- `notes` 现在**只是备注**（程序不解析）—— 形状完全由 `ops` 决定，所以要什么就直接画出来
- 预览是自绘软光栅化，极端角度可能有少量排序瑕疵
